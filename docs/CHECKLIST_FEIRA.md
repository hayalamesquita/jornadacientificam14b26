# Checklist da Jornada Científica

## Uma semana antes

- [ ] Conteúdo científico revisado.
- [ ] Sete animais testados.
- [ ] URL do GitHub Pages definida.
- [ ] QR Code gerado somente depois da URL final.
- [ ] QR Code testado em dois ou mais celulares.
- [ ] Página testada em computador, tablet e celular.
- [ ] Crianças sabem explicar a frase “o micróbio pega uma carona”.
- [ ] Crianças sabem explicar por que o rato é um caso diferente.

## Um dia antes

- [ ] Último `git push` concluído.
- [ ] GitHub Actions verde.
- [ ] URL pública abre em janela anônima.
- [ ] Cópia offline do projeto salva no notebook.
- [ ] Cópia adicional em pen drive ou armazenamento alternativo.
- [ ] Notebook carregado.
- [ ] Carregador separado.
- [ ] Mouse, se for útil para a apresentação.
- [ ] Extensão/filtro de energia, se necessário.
- [ ] QR Code impresso ou exibível.

## Na chegada à escola

- [ ] Conectar o notebook à energia.
- [ ] Testar internet da escola.
- [ ] Abrir a URL pública.
- [ ] Testar pelo menos um celular pelo QR Code.
- [ ] Testar modo tela cheia.
- [ ] Testar um animal, um filtro e o quiz.
- [ ] Se a internet estiver instável, abrir a cópia local.

## Durante a apresentação

- [ ] Começar pela pergunta: “Você sabe o que é um vetor mecânico?”
- [ ] Usar os cards como ponto de exploração, não tentar ler todos os textos.
- [ ] Convidar o visitante a escolher um animal.
- [ ] Mostrar a sequência de transmissão.
- [ ] Finalizar com prevenção ou quiz.
- [ ] Para dúvidas mais complexas, usar o “Saiba mais”.

## Plano de contingência

Se o GitHub Pages ou o Wi‑Fi falhar:

1. usar a cópia local do projeto;
2. abrir com Live Server, se disponível;
3. se necessário, abrir o `index.html` diretamente;
4. continuar a apresentação no notebook sem depender do acesso externo.

> O QR Code depende de internet. A demonstração no notebook não precisa depender dela se os arquivos locais estiverem completos.
